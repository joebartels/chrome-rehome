# ChromeReHome 0.1.3 release evidence

## Build and package

Two separate source copies each started with no installed dependencies or distribution output. On macOS arm64 with Node 24.22.2 and npm 11.19.1, each ran `npm ci` with a fresh cache, then `npm run build` and `npm run check:package`. The strict checker also passed against the working distribution. All three copies contain the same eight files by SHA-256, total 190,800 bytes, with identical esbuild metafiles. The lockfile was byte-identical across the copies. The source manifest, package metadata, both lockfile version fields and built manifest report 0.1.3.

The versioned trial ZIP has deterministic path order, timestamps and mode bits. Building it from each distribution on this host produced identical bytes. ZIP CRC and version readback passed. The 45,050-byte archive SHA-256 is `044aa68ca4064ae332b01c6b1ac5f00782e08d9a3422313a56fadb5f956b597d`. The manifest, background and options bundles differ from the verified 0.1.2 ZIP. The background and options bundles contain the shared configuration repository. The other five files match byte-for-byte. Package reproducibility here covers the pinned toolchain on this host.

The [permission rationale](../../README.md#configuration-and-permissions) maps every manifest permission to a shipped feature. The production entry point creates diagnostics with default options, which disable recording. The diagnostic tests verify that records cannot include raw URLs or arbitrary error payloads even when diagnostics are explicitly enabled. The strict package check scans all three bundled scripts for network and executable-loading primitives and validates the full permission and file inventory. An independent package review reproduced the candidate checks and inspected the permission and diagnostic call sites. The controller rebuilt and compared the corrected package across two new clean source copies.

## Settings verification race

During a repeated Chrome 120 trial, Resume reported Processing unavailable. A separate pre-fix trial on the exact package reproduced the related symptom through Pause. The setting persisted as disabled and the worker still reported unavailable. An independent deterministic test established the underlying source defect. A storage notification can supersede the verification read after a successful save. While the newer read is pending, verification sees no current snapshot and latches a failure even if the newer read later confirms the saved value.

The writer now waits for the already-pending read revision before comparing the latest configuration against the intended value. The optional wait ends if the read is superseded, a newer Pause or Resume is accepted, or controls are disposed. Admission stays closed while verification is pending. An unavailable or mismatched current configuration still fails closed. The regressions cover the successful notification race, genuine mismatch, read supersession, disposal, and a newer Pause while either Resume or Save rules is verifying. They also verify that the optional wait issues no storage reads of its own. Independent review approved the correction.

Node 24 typecheck and 1,391 unit/integration tests across 46 files passed after the correction. The affected Playwright suites passed 100 of 100 portable browser checks on pinned Chromium 156.0.8078.4 with zero skips or retries. The first launch attempt failed before browser startup because the prior temporary cache no longer contained the binary. The final run used a fresh pinned cache with the app and framework metadata verified.

## Browser and performance evidence

The corrected package passed seven checks on Chrome for Testing 157.0.8103.50 on macOS and six on Chrome for Testing 120.0.6099.109 on Linux amd64 with an X11 window manager. Both tested a same-profile unpacked update. The stable run used the real tab-strip menu action and AppKit foreground observations. The floor used the packaged popup document in an inactive extension tab. The floor binary for this Mac exited before the extension ran. The Linux floor ran 24 additional alternating Pause and Resume actions and verified the exact saved settings and worker state for each. [Release qualification](../testing/chrome-release-qualification.md)

The pre-fix package supplied the full 270-trial matrix and the natural idle observations. At 200 tabs, the highest observed trigger-to-acknowledgment p95 across rule counts and background scenarios was 71.1 ms warm and 102.9 ms cold. At 1,000 tabs it was 726.4 ms warm and 894.7 ms cold, with 983 discarded filler tabs in each trial. The corrected package passed 24 instrumented spot checks and four untouched-package outcome checks. The 200-tab local targets are 125 ms warm and 175 ms cold. The report retains the full method, budgets, API counts, and high-tab cold badge reconciliation cost.
