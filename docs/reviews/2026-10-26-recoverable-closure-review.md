## Strengths

- **Placement, closure, and restart admission ship as one mechanism.** Production constructs one native port, journal, recovery object, and coordinator queue; listeners register before initialization. The initialization promise joins configuration and queue-owned recovery before consume jobs enqueue. Admission and running contexts require recovery readiness, and the consumer guard additionally includes the journal block and original event/lease (`src/background/index.ts:14`, `src/background/coordinator.ts:32`, `src/background/placement.ts:57`). Grouping-only operations receive the same journal coverage.
- **Write-ahead ordering preserves actual native settlement.** Placement and removal await pending persistence, repeat their complete preflight, and check the current guard immediately before invocation. There is no executor storage await between final removal validation/arming and the call. Both native resolution and rejection attempt settlement bookkeeping before returning; an additional storage failure blocks future work without replacing the native rejection. Failed pending/settled/verified/terminal/clear persistence does not trigger repair writes. Cancellation after a pending write can be abandoned only by the live executor, after every issued native call has settled (`src/execution/placement.ts:139`, `src/execution/replacement.ts:90`, `src/execution/replacement.ts:145`). No timeout releases the queue.
- **Closure uses independent evidence and an immutable receipt.** Passive document absence/error/nonactive/subframe state makes closure ineligible while valid configured placement remains possible. Every remaining participant is rechecked between coherent snapshots before each remove. Strict original href, captured document identity, context/pin/pending state, affected-window survivors/order, and group metadata remain guarded. The widened placement window set prevents passive-window changes from being adopted as a new receipt baseline (`src/execution/placement.ts:44`, `src/execution/replacement.ts:41`, `src/execution/replacement.ts:74`).
- **The earlier destructive-work verification defect is closed.** `src/execution/replacement.ts:45` rejects every claimed-absent ID across the full authoritative snapshot before affected-window filtering. Both post-call bracket reads and later preflights use this check. An attempted target enters the verified prefix only after both brackets succeed. The two new regressions exercise a fulfilled target relocation and reappearance before the final bracket, requiring an uncertain target, no verified target, no subsequent close, and no journal verification write (`tests/unit/replacement-execution.test.ts:140`, `:161`).
- **Removal feedback is narrow and irreversible.** A lease starts stale if its original view is not current; only a single armed allowlisted ID can earn a revision credit, and only while the lease was current immediately before that event. Delayed events can arrive during a later removal, while unexpected/repeated removals, navigation, and both replacement paths still invalidate. Disposal is permanent and occurs in the consumer finally block (`src/background/navigation.ts:65`, `:116`, `src/background/placement.ts:65`).
- **Journal persistence is bounded and privacy-conscious.** Parsing distinguishes missing from invalid, validates own keys/dense arrays/context/IDs/prefix/pending/terminal structure, and returns detached frozen records. The native adapter touches only the one session key; no URL, URL-derived identity/hash, title, config copy, timestamp, error, or tracker epoch/generation enters the schema. Occupied begin and ambiguous persistence failures close admission (`src/execution/journal.ts:38`, `:88`, `src/browser/journal-storage.ts:3`).
- **Recovery is conservative rather than replayable.** Pending records are preserved without interpreting matching or absent participants as settlement; malformed/future/unreadable records are not repaired. Settled records receive one read-only snapshot and are cleared without any native mutation. The reconstructed-worker deferred tests leave the discarded promise unresolved and demonstrate that late effects/events and configuration toggles do not admit new work (`src/background/recovery.ts:12`, `tests/integration/recovery.test.ts:36`).
- **Tests and docs distinguish modeled guarantees from native observations.** Production browser cases assert older-ID disappearance, retained unrelated IDs, destination/index/group membership, winner history, and empty source/duplicate structures. Phase tests use the actual production modules in temporary fixtures. Seeded recovery and simulated rejection are labeled honestly. README begins with the already-enabled upgrade warning, includes backup/disable-before-reload/enable/pause/restore steps, and explains quarantine, partial completion, the participant cap, and residual risks. Options describes configured enablement without claiming recovery readiness.

## Whole-feature reasoning and plan alignment

The production ordering is coherent across modules, including the less obvious failure edges. A journal begin failure occurs before native work. A failed preflight after pending persistence reaches abandonment only while the executor still knows whether it invoked the call. A rejected native call is awaited and its original cause retained. A failed settlement write blocks abandonment rather than rewriting uncertain durable state. A successfully settled but unverified removal stops with an uncertain target and does not close the next duplicate. A verified removal remains in the reported prefix even if its subsequent journal write fails, accurately separating live observation from durable bookkeeping. A stale lease never recovers through a later expected event.

The receipt validator preserves all affected-window survivors and group metadata, permits only expected empty-structure disappearance, and now proves claimed removal absence across the complete snapshot returned by the all-normal-windows port.
