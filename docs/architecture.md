# Foundation architecture

The worker and options page are independent ES module entry bundles. Configuration contracts are shared; options does not import background orchestration. Browser state remains authoritative, and snapshots are read-only observations rather than transactions.

| Module | Ownership and next integration point |
| --- | --- |
| `background/index.ts` | Wire dependencies and synchronously register every required listener before initialization. |
| `background/register-events.ts` | Observe committed/history/fragment navigation, pre-navigation invalidation, tab removal, both native replacement APIs, audible authority revocation and install/startup. Integration tests cover registration and delayed initialization. |
| `background/coordinator.ts` | Await shared config/protection/recovery readiness, validate generations and enqueue normalized work with immutable configuration and protection captures. |
| `background/navigation.ts` | Admit conservative metadata/provenance-qualified main-frame events; worker epoch, generations and whole-view revisions reject stale work. |
| `background/operation-queue.ts` | Serialize jobs until settlement and recover after rejection. Native settlement holds this queue; the session journal supplies the restart uncertainty barrier. |
| `background/controls.ts` | Serialize configuration/protection intent and lifecycle cleanup; synchronous admission barrier independent of native settlement. |
| `controls/` | Neutral strict commands, versions, per-request target receipts and one-shot UI client. |
| `protections/` | Strict bounded session identities and verified repository; no browsing content is persisted. |
| `config/` | Pure schema, validation, migration dispatch and repository; no Chrome globals or browser-adapter imports. |
| `rules/grouping.ts` | Pure ordered wildcard compiler using native `URLPattern`; shared validation for strict legacy schemas and canonical schema 4, options preview and planning. No browser globals or config/background/options/browser imports. |
| `rules/duplicates.ts` | Pure exact-origin duplicate identity compiler using native `URL`/`URLSearchParams`, immutable policies and a lossless raw query token adapter. Used by the production placement consumer. |
| `planning/candidates.ts` | Pure snapshot/current-view winner and anchor selection through supplied duplicate identity; no execution authority. |
| `planning/group-destination.ts` | Pure exact-title destination selection with a backwards-compatible own-window default and explicit all-normal-windows production scope. |
| `execution/group-placement.ts` | Opt-in queue-backed grouping and bounded fresh verification through an injected structural port; no production caller. |
| `browser/` | Narrow Chrome adapters for storage, snapshots and explicit grouping/title mutation. Group placement observations omit URLs. |
| `diagnostics/` | Bounded, opt-in, redacted diagnostic records; no telemetry or raw URL/query logging by default. |
| `options/` | Pure draft/preview model, async editor controller and native DOM view; shares config contracts through browser adapters without background coupling. |

Every worker start constructs dependencies, registers listeners synchronously and initiates configuration loading. Event handlers await initialization; no asynchronous initialization gates listener registration. Errors preserve stored configuration and disable processing. Session journal v2 (with strict v1 read compatibility) provides a bounded durable pending-native barrier; recovery must be ready before automatic mutation.

Grouping rules and duplicate equivalence are independent pure concepts. `compileGroupingRules(unknown)` returns immutable rules plus `match(url)` or an indexed validation error. It parses each configured HTTP(S) URL with `URL`, escapes native metacharacters except `*`, and compiles reusable component-based `URLPattern` objects. HTTP and HTTPS alternatives for `*://` normalize default ports independently. Candidate search/hash are ignored, first active configured match wins, path case/encoded delimiters remain significant, and invalid candidates return undefined. Rule validation is atomic and bounded (100 rules, 2048 code units per pattern, 80 per group title). See [Task 001](tasks/todo/001-wildcard-group-rules.md) for examples and constraints.

`compileDuplicateRules(unknown)` returns frozen exact-origin rules and `match({url, incognito})`/`identify({url, incognito})`/`equivalent(left, right)` or an indexed atomic validation error. Native `URL.href` defines conservative identity, preserving meaningful paths, query bytes/order/repeats and fragments. Only a matching explicit origin policy enables parameter deletion, stable decoded-name query sorting, fragment removal or trailing-slash removal. Native `URLSearchParams` supplies decoded names and sorting; raw retained tokens are carried by temporary indices, avoiding reserialization of invalid byte sequences or escape spelling. Empty fields retain their remaining slots. Keys are opaque namespaced JSON tuples containing explicit browsing context and canonical href; invalid candidates have no identity and never match. Keys contain sensitive URL data and are never logged, persisted or navigated to. Future planning must pass actual incognito metadata. See [Task 002](tasks/todo/002-duplicate-url-equivalence.md) for the policy decisions.

`Config` and `ConfigState` remain owned by `config/schema.ts`. Canonical config is `{ schemaVersion: 4, enabled: boolean, groupingRules: readonly ConfigGroupingRule[], duplicateRules: readonly ConfigDuplicateRule[] }`, with a required boolean enabled on every rule. Missing config defaults to disabled v4. Strict v1–v3 migrate in memory and enable their legacy rules while preserving global activation, order and field values. Schema-specific shape checks keep legacy input strict. Compilers accept their exact legacy shapes or those fields plus boolean enabled, preserving that field's presence in public compiled rules. Disabled rules remain validated, bounded, copied and frozen, but do not match. Duplicate canonical-origin uniqueness includes disabled rules; disabling a policy restores conservative identity. Loads never persist migrations or overwrite invalid/future input. Explicit validated saves write one v4 document. The default-disabled production consumer uses the current published config revision.

Task 007 options reuse the actual compilers through `options/model.ts`; grouping candidate validation is shared with the runtime, while duplicate `match` reports the same active policy used by identity. Preview returns readable policy/group/comparison results without returning opaque identity strings. URL inputs stay in the view's memory and never enter controller settings, storage or diagnostics. The controller separates draft, base configuration and latest observed saved state. It subscribes before load, preserves dirty drafts on observed conflicts, and validates before save. Save refreshes the base, performs one whole-document write and verifies a fresh read before acknowledging success. Errors retain drafts and release busy state for retry; controller generations/disposal guard asynchronous continuations. Chrome storage has no transactional compare-and-swap, so a concurrent writer between preflight and write remains a documented race. The native DOM retains input nodes during typing, with labeled keyboard-accessible row actions and inline validation. Global activation remains unchanged; Task 008 owns pause/protection controls.

`planGroupDestination(request, snapshot)` resolves a literal, case-sensitive configured title in the request tab's explicit window/context. It prefers the source's current matching group, otherwise lowest observed member index then group ID. A matching orphan or contradictory membership skips conservatively. Pinned/missing/moved/context-changed tabs skip. The planner validates concrete nonnegative safe integer IDs and the existing 1–80 code-unit title contract, and preserves readonly inputs.

`createGroupPlacementService({port,queue}).place(request)` reads/plans twice before grouping. The newer coherent snapshot can recover a torn initial snapshot; the latest skip prevents mutation. It verifies authoritative membership/window/context/pinning after grouping, requires exact title on reuse, and names a new group only when its title is absent/empty. An external nonempty rename is not knowingly overwritten. A successful title update requires one final read. Results distinguish observed placement, skip and failed read/group/title/verification with original causes and known partial effects. A rejected grouping call has uncertain effects; a rejected title call may leave a real unnamed group. There is no mutation retry, cleanup or rollback. Chrome may expand/reposition groups itself; returned success is an observation that can immediately become stale.

The browser adapter supplies `tabs.group({tabIds:[tabId],groupId})` for reuse or `tabs.group({tabIds:[tabId],createProperties:{windowId}})` for creation. Only `{title}` goes to `tabGroups.update`; all titles are read with `tabGroups.query({windowId})`, avoiding native title-pattern semantics. No URL leaves this adapter's snapshot mapping.

When eventually wired, retain one group-placement service and dedicated shared queue per worker, injecting the existing `createOperationQueue()` structurally. This queue must differ from any outer coordinator queue whose active job awaits `place`, to avoid a nested queue deadlock. Serialization includes final verification and survives per-call failures within one service lifetime; it does not coordinate external actors, other instances or restarts. The production placement executor reuses this resolver and native methods directly inside the coordinator queue, never this nested queued service. The replacement executor independently supplies closure evidence and startup recovery around the production path.

Build checks scan typed source, including erased type imports, and inspect esbuild's emitted dependency graph. Source guards permit only the exact `rules/grouping` and `rules/duplicates` validators as dependencies outside `config/` for config validation, reject rules imports outside `rules/`, limit planning to planning/rules and execution to execution/planning, reject external packages (including scoped names) from these layers and browser globals in all four layers, and reject options/background coupling and UI code in worker bundles. The scanner uses the pinned TypeScript 7 AST scanner entry point, whose API must be rechecked during dependency upgrades. Package checks deliberately enforce this small project's invariants; they are not a general JavaScript security analyzer.

Browser smoke confirms load, options errors, byte-preserved saved rules across reload and worker restart, unchanged legacy/invalid/future storage, unchanged tab/group snapshots, stopped/running CDP worker state and a fresh JavaScript realm after navigation. A compiler bundle generated in a temporary test fixture runs the same hand-checked literal/wildcard/query/hash/port matrix as Node against native Chromium `URLPattern`. A separate temporary bundle runs the shared duplicate corpus against native Chromium `URL`/`URLSearchParams`, including invalid bytes, empty tokens and context separation. No fixture enters the extension package. Production-dist placement browser tests additionally prove observable grouping, membership, order, retained IDs and winner history. Deterministic synchronous registration, navigation dispatch and delayed initialization are covered by integration tests. There is no production test endpoint or worker keep-alive.

An isolated temporary extension fixture bundles the actual group placement service/adapter for real browser tests of creation, reuse, exact titles, duplicate selection, own-window isolation, pinning, last-member removal and partial failure. It records Chromium version, Chrome-owned collapse state and extension incognito capability. Incognito access is unavailable unless explicitly enabled for that fixture; a capability result is not a claim of incognito placement coverage. See Task 003 for the unautomated disposable-profile check.


Navigation admission is synchronous before any configuration await. Active ordinary committed metadata can establish document provenance even at cold worker start. Valid `start_page` commits can also establish provenance, including configured startup URLs. Core reload (including address-bar-qualified reload), missing/unknown metadata and nonactive lifecycle cannot. Server redirects use final commits; qualified client redirects require trusted source provenance preserved across before-navigate. New history/fragment candidates require the trusted document, changed native href and no pending full navigation. A fully validated eligible history/fragment event preserves existing unblocked navigation/provenance only when its document, parsed href and exact URL bytes still match that admitted navigation. It emits no candidate and changes no revision, generation, sequence or valid removal lease; only the latest deduplication fingerprint changes. This narrow no-op exception cannot revive blocked/missing navigation or a stale view/lease. Changed URL bytes (even with equal parsed href), invalid/ineligible metadata and pending navigation still revoke work; delayed foreign-document events cannot acquire provenance. Both replacement APIs clear both identities/provenance and block the added ID without rank transfer. Error/canceled navigation remains conservatively blocked until a later active commit.

This is a metadata policy, not human-intent or universal restoration detection. **Unqualified script navigation reported as ordinary link can qualify after reload or cold worker start.** A real Chromium worker-restart probe observed exactly that admission for a delayed script; it did not report client_redirect. Qualified cold-client rejection is unit gated; the immediate trusted client redirect is browser observed. `start_page` is admitted under the [27 October compatibility amendment](tasks/todo/006a-external-app-link-compatibility.md), including configured startup pages sharing this metadata; origin and user intent are not inferred. Cold SPA/hash events and prerender activation without a qualifying commit remain deliberate false negatives. See [Task 004](tasks/todo/004-navigation-eligibility-and-winner-selection.md) for policy and manual capability gaps.

Tracker epochs are fresh Symbols; numeric generations/sequences never cross worker lifetimes or persistence. Whole-view revisions include previously unobserved anchor invalidation. State retains only latest per-tab fingerprint, trusted document, eligible event and block status. Views and returned selections contain detached frozen observations. Selector inputs contain no Chrome/background types. It validates unique IDs/counters/context and obtains identity only from the supplied duplicate compiler using snapshot URLs/incognito. PendingUrl property presence, pinning, blocking or snapshot/event native-href inconsistency excludes a participant. Strict native URL freshness is independent of relaxed duplicate equivalence. Latest observed eligible sequence wins, with lowest-tab-ID ties; passive duplicates are ordered by winner window, window ID/index/tab ID for anchor choice.

The production placement consumer captures a tracker view BEFORE the existing all-normal-windows snapshot read and verify that same revision afterward, then revalidate event/view plus actual participant URLs/context/location around downstream async work. Pairing an old snapshot with a newly captured view is unsafe. Selections return no mutation plan or closure authority; production placement grants no closure authority. The temporary navigation browser bundle records real metadata and pending snapshots, worker-restart provenance loss and a bounded native prerender probe. No test endpoint, event fabrication or keep-alive enters production. A separate macOS LaunchServices test loads untouched production `dist` in a uniquely cloned bundled Chromium app with its own random profile. It asserts the external survivor is grouped and its older duplicate closed for HTTP, HTTPS, cross-scheme final identity and confirmed stopped-worker HTTPS; the disabled native control retains both tabs ungrouped. The metadata observer remains separate from these production behavior tests. Native restore/reopen commits were not captured, and trusted omnibox UI remains a documented disposable-profile manual check.


## Task005 production placement (previous placement-only phase)

`background/placement.ts` captures the tracker view before its all-normal-windows snapshot, compiles the captured grouping/duplicate rules and opts into lone-winner selection through the same validated selector path. `planning/replacement.ts` freezes one final destination and detached participants/baseline. Under the 27 October manual-organization amendment, the selected duplicate anchor supplies its live window/group (including ungrouped) and after-anchor position before any grouping rule. Only a lone winner resolves configured grouping through003’s pure resolver with the explicit all-normal-windows scope. It prefers current group, then local group, then remote groups ordered by window/index/group ID. A planned new group remains authorized only while no other exact-title group in the same context appears anywhere in the normal-window snapshot, including before naming a freshly created group; a late match stops without replanning or rollback and may leave the already-created group unnamed. No destination means unchanged. Passive duplicate documents are optional; only the winner and a used inherited anchor receive frame0 document reads (at most two per observation round). The selected anchor always needs live document evidence even when a grouping rule matches; unavailable evidence never falls back to a configured destination. Task006 must obtain independent closure evidence.

`execution/placement.ts` owns no queue. Before each mutation it brackets used participant document checks with normal-window snapshots and checks the config/event/view lease around every await. A separate expected state accounts for acknowledged winner operations while the frozen plan stays unchanged. Nonwinner relative order/membership in source and destination windows, strict native URLs/context/pinning/pending state, source/destination group coherence/title/shared metadata and used document IDs stay guarded. A lone emptied old group/source window may disappear; surviving tabs may not. Known shared groups cannot acquire or lose the winner; absent shared metadata supports Chrome120.

The bounded operation sequence ungroups only when needed, moves across windows directly to the final destination boundary, joins/creates only the final group, titles a fresh group only when empty, and performs at most one final reorder. After-anchor index is computed with the winner removed exactly once. Final membership/window/order are authoritatively observed. Foreground attention is guarded and explicitly presented after structural placement as described below; preserve intent issues no activation/focus calls. Chrome-owned collapse expansion from activation is accepted. No tabs are created/closed, no retry/rollback occurs, and mutation promises always settle before the coordinator queue releases. Results preserve original rejection causes and uncertain/acknowledged/verified effects; diagnostics emit only redacted `operation-failed` codes.

Repository `getCurrent()` publishes an in-memory revision lease only for the settled current operation. Load/save starts and disposal revoke it; a storage notification starts load synchronously. Coordinator contexts combine that publication with its own revision/disposal and event ownership. Consumer guards additionally require the captured whole tracker view, so unrelated navigation can cancel work conservatively. Default configuration remains disabled; manual schema 4 enable/pause/backup/restore steps and browser capability limits are in the README. Native APIs cannot eliminate the final check-to-call race.

## Task006 journaled replacement and recovery

`execution/replacement.ts` wraps the existing queue-free placement executor and single-ID removals inside the coordinator job. It captures passive duplicate frame0 documents independently, without turning missing unused-passive documents into placement requirements. Required anchor evidence still gates placement. The final successful placement receipt is detached/frozen. Closure checks all remaining participant documents between coherent snapshots and compares affected windows/groups to that receipt minus verified removals. Strict original native href equality and original document IDs are required even with relaxed duplicate policy. Native active/focus/collapse changes remain accepted; all surviving IDs/order/membership/window/group title/color/shared/context/pin/pending evidence remains guarded. The single target must be authoritatively absent after native settlement before another removal can proceed.

`execution/journal.ts` owns strict bounded version-aware v1/v2 parsing and serialized transitions through injected structural storage. The only key is `chromeReHomeReplacementJournal`, adapted by `browser/journal-storage.ts` to storage.session get/set/remove with unchanged trusted access. One record contains operationId, native participant IDs/context/document IDs, phase, mutation sequence, pending target, verified removed prefix and terminal state. Limits are 100 participants, 99 removals, 128 code units/string, 65536 serialized characters and 105 ordinals for v1 or 107 for v2. New operations write v2; v1 rejects the new activate/focus mutation and phase names. More than 100 participants skips all mutation. No URL, identity/hash, title, configuration, error, timestamp, Symbol or tracker generation is persisted. Native document IDs are sensitive session metadata and never sufficient authority for replay.

Every placement mutation, including repeated move/final reorder, persists pending before repeating the entire original preflight. Both resolve/reject settlement paths clear pending durably; native rejection identity survives a second bookkeeping failure. Authoritative postverification precedes phase persistence. `placed` is durable before any close. Removal repeats full receipt/document/config/event checks after pending persistence, arms exactly one lease credit and invokes the one-ID native remove without another executor await. Terminal completion/abandonment precedes clear. Ambiguous storage failure blocks admission and never triggers repair writes. A preflight cancelled before native invocation may be abandoned by its still-live worker; restart cannot infer that distinction.

`background/navigation.ts` removal leases retain the original revision/epoch and immutable duplicate allowlist. Each issued ID credits only its first onRemoved event while the lease was current immediately before it. Earlier issued events may arrive during the next remove. An unexpected/duplicate event, navigation/invalidation or either replacement API remains fatal; later credited events never revive stale work. Consumer disposal permanently invalidates the lease. Ordinary tracker forgetting/revision advancement still occurs for every event.

`background/index.ts` constructs one native port, one session journal (operation IDs injected using crypto.randomUUID), one recovery object and one queue. Listeners register synchronously first. Coordinator initialization joins config loading with recovery on that same queue; consume jobs await the entire promise before enqueueing. Current config publication and recovery/journal readiness also remain part of running guards. Recovery runs regardless of enabled/config validity. Missing storage becomes ready; valid settled records await one read-only live snapshot as the reconciliation gate before clear/abandon; pending, malformed, future or unreadable records preserve data and quarantine all automatic mutation. Participant presence never authorizes replay. Read/clear failure blocks. A native call is never raced against a timeout, and a new worker cannot issue work across the persisted pending barrier even after an old worker's late effect/event. Recovery never replays placement/closure.

Full browser restart is the reliable reset for ambiguous native settlement, followed by an explicit fresh trial. Session clearing by disable/reload/update does not prove native settlement. Chrome has no atomic compare-document-and-remove operation; the residual final check-to-call race remains. No unsaved-form protection or stronger transaction guarantee is claimed. Existing enabled schema3 installations activate closure on upgrade; README begins with the pause-before-reload warning and options states configured replacement enablement plus a static interruption warning.

Automated evidence separates unchanged production dist (closure, native indices/history, seeded restart admission) from temporary phase fixtures (actual worker termination after durable writes, event-delivery races, simulated faults). Production has no test globals/endpoints/keep-alive. Pending-write gates are before native invocation; a separate fulfilled-remove wrapper gate proves already-issued effect without recorded settlement. Deterministic termination inside an outstanding native Chrome API remains unproven by the browser; deferred old-worker tests retain its unresolved call and show fresh-coordinator quarantine after late effects. Manual actual drag, incognito capability enablement and Chrome120/current-stable trials remain required; isolated headed macOS production tests cover native focus/collapse behavior.


## Task007b foreground presentation

`planning/presentation.ts` classifies intent from the raw first placement snapshot's unique active source selection and a corroborating populated normal-window attention observation. `CandidateTab` copying and duplicate ordering remain unchanged. Missing, contradictory, duplicate or unavailable attention evidence produces preserve intent while valid structural placement can proceed; later activation never promotes that intent. The native adapter reads `windows.getAll({populate:true,windowTypes:['normal']})`, retaining detached active IDs and the uniquely focused window. No attention state is persisted.

`execution/presentation.ts` maintains the in-memory receipt while the existing placement executor owns all mutations. Foreground authority requires the source selection/focus to remain unchanged around structural/document reads and durable pending/settled/verified checkpoints. A cross-window move may deactivate the incoming tab and choose a source successor; only a surviving source tab may become that successor, destination and other windows must keep their selections, and the source stays focused. A disappeared source permits continuation only with observed destination focus. The successor is then frozen as the receipt; arbitrary user selection/focus changes cannot become a new baseline.

After structural placement, the same awaited mutation helper journals `activate` then `focus` as necessary, calls exactly `tabs.update(id,{active:true})` and `windows.update(id,{focused:true})`, and verifies incoming selection and destination focus. Already satisfied actions are no-ops. Activation naturally reveals a collapsed destination group. Native focus can restore a minimized destination without another mutation primitive. Both pending records target the winner tab ID and are legal only before `placed`. They have the existing pending-write, complete preflight, native await, settlement, verification, and verified-phase protocol. Native rejection identity survives settlement bookkeeping failure; unresolved native promises retain the sole queue and their durable admission barrier. Recovery reads both versions without replaying presentation or closure.

The successful placement receipt includes detached attention only in memory. Replacement checks it again after durable `placed` persistence, before closure. This accepted barrier ends presentation authority; closure then uses the existing strict document/snapshot/removal lease checks. Focus-only changes during later closure do not authorize further presentation calls or introduce another attention state machine. Background placement performs zero activation/focus mutations and preserves surviving active spare tabs, focused windows and group collapse under native behavior. Removing an active duplicate or emptying a source can necessarily select a successor; removed tabs/windows cannot retain attention.

Snapshots cannot distinguish a user choosing the same successor during Chrome's move, switching away and back between observations, or acting in the final check-to-native-call interval. These non-atomic limits remain explicit; there is no activation event tracker, retry, rollback, timeout race, synthetic navigation, or tab recreation. Portable deferred-native tests retain a discarded worker's unresolved call and prove fresh-worker quarantine after its late effect. Actual headed worker termination tests separately gate pending/settled/verified presentation writes and native-fulfilled wrappers; they do not claim deterministic interruption inside Chrome's native API.

Production evidence uses isolated headed macOS Chromium with actual foreground clicks, deliberate Cmd-click background opens, remote rule/manual-group/ungrouped destinations, a lone source, and a minimized destination. Independent LaunchServices tests open real OS external URLs into remote grouped/ungrouped/rule destinations and poll native active/focused IDs. These tests are capability-skipped outside macOS; headless reuse tests remain portable and do not treat multi-focused headless metadata as native focus proof. No test controls enter production dist.

The unchanged-history regression uses the real tracker/coordinator/consumer and a real page `history.replaceState` while a test-only wrapper holds an already-fulfilled corrective move before settlement. Foreground presentation and duplicate closure proceed; Cmd-click stays background, and changed-URL history still cancels before presentation/closure. This scheduling gate is not evidence of native API interruption. The same failure and correction were observed on isolated Chrome for Testing155.0.8059.84 as well as the regular Chromium156 suite.

A separate untouched-dist LaunchServices case starts from an owned empty AppKit helper: its NSWorkspace frontmost PID matches its owned child process, and every isolated Chrome window is unfocused before OS open. Repeated same-URL history events occur during the journal operation, and the remote Group A destination is verified active/focused. The helper and browser profile are temporary; no personal application is automated. This proves the measured external handoff, not every macOS Spaces or application timing combination.


## Task008 worker controls and session protections

`background/controls.ts` owns one serialized configuration/protection writer, independent of the native-operation queue. Accepted commands synchronously advance control generation and close admission before any queued or storage await. Enabled-command cancellation tickets remain separate from rule/protection/lifecycle writes, so cleanup cannot cancel a queued pause. Immutable captures carry configuration plus the exact session protection identities through `ConsumeContext` into both candidate selection and plan re-selection. A stale operation cannot acquire new authority after resume or unprotect.

`protections/state.ts` strictly parses `storage.session.chromeReHomeProtections` as `{version:1,tabs:[{tabId,incognito}]}`, with unique bounded tab IDs and at most 1000 entries. Missing is empty; malformed, unknown, future or unreadable state remains unavailable without erasure. No URL, title or document data is stored. Additions at the bound are refused, without eviction. The repository detaches and freezes snapshots, revokes publication at read/write start, and lets only the newest operation publish as current. The sole writer verifies every write by reading it back. One exact canonical value echo from its own write is consumed; a different external value immediately revokes and reloads. This is an exact-value echo credit, not an exemption around an await or distributed compare-and-swap.

Initial admission joins config/session readiness and recovery, then prunes absent or mismatched live tab identities. Only the synchronous invalidation callbacks for the owned initial reads and owned prune write are exempt from navigation cancellation; external changes and user intent still revoke startup navigation. Failure to verify live identities or persist startup pruning latches unavailable for the worker lifetime, including after a valid explicit pause. Other uncertain control writes retain a conservative failure gate until fresh verified intent. Commands and lifecycle cleanup share the writer queue, and forgetting an unprotected ID is an authority no-op so tracker-issued native removal credits survive every duplicate close. Removal/replacement ends protection without transferring it. Navigation/reload and worker suspension retain it; Chrome session-storage lifetime ends it at browser/extension restart.

Global `get-status` remains synchronous in the service and returns no target. An optional UI-owned `{tabId,windowId,incognito}` hint is independently verified using that window's selected tab and active outermost document, with selection checked again after document lookup. A per-request target contains only `{receipt,protected,audible,pinned}`; no last-focused private window or global target cache is consulted. Protection commands compare the displayed document receipt before and after persistence. A stale postwrite unprotect conflicts and keeps admission unavailable until fresh verified intent; no rollback or retry attempts to reconstruct intent. Valid paused configuration permits protection preparation without enabling processing. Unknown/unavailable configuration or protections, unavailable documents, or blocked recovery cannot authorize a protection change or unsafe resume. Explicit pause remains available when configuration can be persisted.

`planning/protections.ts` contains the pure tab identity policy. Candidate metadata explicitly includes audible state; a protected or audible incoming winner skips automatic work. Older protected/audible duplicates retain their original anchor priority. Their presence permanently makes the entire selected plan closure-ineligible, while otherwise-valid winner placement may inherit the existing manual location. Both initial and checked decisions must permit closure; document-based eligibility can only restrict it further. The journal's participant/removal-prefix grammar is unchanged. Protected old tabs themselves are not moved or closed.

Both executors recheck participant audio against the frozen plan at existing snapshot/document barriers. Removal additionally requires all remaining participants to be silent after pending-remove persistence and immediately before its native call. Unrelated-tab audio is not part of structural equality. Audible `tabs.onUpdated` notifications revoke control generation independently of navigation provenance, so subsequent legitimate same-document history stays eligible. Already-issued native promises remain awaited and may finish; Chrome provides no atomic silent/document-conditional removal API. No automatic form inspection, recency cache, polling, keepalive, permission, dependency, configuration schema or package expansion is introduced by this backend task.


Task008 native tests use a test-only `owned-browser-focus.ts` precondition for focus-dependent headed cases: it derives the isolated browser PID via its browser-level CDP session, activates only that PID through AppKit, and verifies the actual OS frontmost PID. Native window/tab assertions remain unchanged. A denied foreground transition fails explicitly before the focus scenario rather than inventing focused flags. Protection/audio checks use actual headed tabs and audio metadata without requiring unrelated OS foreground state. Incognito access is recorded as a capability; it is not enabled or inferred by these fixtures.
