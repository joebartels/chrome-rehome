# Foundation architecture

The worker and options page are independent ES module entry bundles. Configuration contracts are shared; options does not import background orchestration. Browser state remains authoritative, and snapshots are read-only observations rather than transactions.

| Module | Ownership and next integration point |
| --- | --- |
| `background/index.ts` | Wire dependencies and synchronously register every required listener before initialization. |
| `background/register-events.ts` | Observe committed/history/fragment navigation, pre-navigation invalidation, tab removal, both native replacement APIs and install/startup. Integration tests cover registration and delayed initialization. |
| `background/coordinator.ts` | Await one shared initialization, validate generations and enqueue normalized work. Captures a published config revision and admits replacement only after configuration and queue-owned recovery initialization. |
| `background/navigation.ts` | Admit conservative metadata/provenance-qualified main-frame events; worker epoch, generations and whole-view revisions reject stale work. |
| `background/operation-queue.ts` | Serialize jobs until settlement and recover after rejection. Native settlement holds this queue; the session journal supplies the restart uncertainty barrier. |
| `config/` | Pure schema, validation, migration dispatch and repository; no Chrome globals or browser-adapter imports. |
| `rules/grouping.ts` | Pure ordered wildcard compiler using native `URLPattern`; shared validation for legacy schema 2 and canonical schema 3 and future preview/planning. No browser globals or config/background/options/browser imports. |
| `rules/duplicates.ts` | Pure exact-origin duplicate identity compiler using native `URL`/`URLSearchParams`, immutable policies and a lossless raw query token adapter. Used by the production placement consumer. |
| `planning/candidates.ts` | Pure snapshot/current-view winner and anchor selection through supplied duplicate identity; no execution authority. |
| `planning/group-destination.ts` | Pure exact-title own-window destination selection and structural request/snapshot contracts. |
| `execution/group-placement.ts` | Opt-in queue-backed grouping and bounded fresh verification through an injected structural port; no production caller. |
| `browser/` | Narrow Chrome adapters for storage, snapshots and explicit grouping/title mutation. Group placement observations omit URLs. |
| `diagnostics/` | Bounded, opt-in, redacted diagnostic records; no telemetry or raw URL/query logging by default. |
| `options/` | Minimal installation/configuration status; shares config contracts through browser adapters. |

Every worker start constructs dependencies, registers listeners synchronously and initiates configuration loading. Event handlers await initialization; no asynchronous initialization gates listener registration. Errors preserve stored configuration and disable processing. Session journal v1 provides a bounded durable pending-native barrier; recovery must be ready before automatic mutation.

Grouping rules and duplicate equivalence are independent pure concepts. `compileGroupingRules(unknown)` returns immutable rules plus `match(url)` or an indexed validation error. It parses each configured HTTP(S) URL with `URL`, escapes native metacharacters except `*`, and compiles reusable component-based `URLPattern` objects. HTTP and HTTPS alternatives for `*://` normalize default ports independently. Candidate search/hash are ignored, first configured match wins, path case/encoded delimiters remain significant, and invalid candidates return undefined. Rule validation is atomic and bounded (100 rules, 2048 code units per pattern, 80 per group title). See [Task 001](tasks/todo/001-wildcard-group-rules.md) for examples and constraints.

`compileDuplicateRules(unknown)` returns frozen exact-origin rules and `identify({url, incognito})`/`equivalent(left, right)` or an indexed atomic validation error. Native `URL.href` defines conservative identity, preserving meaningful paths, query bytes/order/repeats and fragments. Only a matching explicit origin policy enables parameter deletion, stable decoded-name query sorting, fragment removal or trailing-slash removal. Native `URLSearchParams` supplies decoded names and sorting; raw retained tokens are carried by temporary indices, avoiding reserialization of invalid byte sequences or escape spelling. Empty fields retain their remaining slots. Keys are opaque namespaced JSON tuples containing explicit browsing context and canonical href; invalid candidates have no identity and never match. Keys contain sensitive URL data and are never logged, persisted or navigated to. Future planning must pass actual incognito metadata. See [Task 002](tasks/todo/002-duplicate-url-equivalence.md) for the policy decisions.

`Config` and `ConfigState` remain owned by `config/schema.ts`. Canonical config is `{ schemaVersion: 3, enabled: boolean, groupingRules: readonly GroupingRule[], duplicateRules: readonly DuplicateRule[] }`. Missing config defaults to disabled v3. Strict v1 migrates with both lists empty; strict v2 preserves grouping rules and adds empty duplicate rules. V3 delegates validation to both pure compilers and copies/freezes accepted data. Loads never persist migrations or overwrite invalid/future input. Explicit validated saves write v3; repository ordering, subscriber notification and write-failure behavior are unchanged. The options UI remains read-only. The default-disabled production consumer uses the current published config revision.

`planGroupDestination(request, snapshot)` resolves a literal, case-sensitive configured title in the request tab's explicit window/context. It prefers the source's current matching group, otherwise lowest observed member index then group ID. A matching orphan or contradictory membership skips conservatively. Pinned/missing/moved/context-changed tabs skip. The planner validates concrete nonnegative safe integer IDs and the existing 1–80 code-unit title contract, and preserves readonly inputs.

`createGroupPlacementService({port,queue}).place(request)` reads/plans twice before grouping. The newer coherent snapshot can recover a torn initial snapshot; the latest skip prevents mutation. It verifies authoritative membership/window/context/pinning after grouping, requires exact title on reuse, and names a new group only when its title is absent/empty. An external nonempty rename is not knowingly overwritten. A successful title update requires one final read. Results distinguish observed placement, skip and failed read/group/title/verification with original causes and known partial effects. A rejected grouping call has uncertain effects; a rejected title call may leave a real unnamed group. There is no mutation retry, cleanup or rollback. Chrome may expand/reposition groups itself; returned success is an observation that can immediately become stale.

The browser adapter supplies `tabs.group({tabIds:[tabId],groupId})` for reuse or `tabs.group({tabIds:[tabId],createProperties:{windowId}})` for creation. Only `{title}` goes to `tabGroups.update`; all titles are read with `tabGroups.query({windowId})`, avoiding native title-pattern semantics. No URL leaves this adapter's snapshot mapping.

When eventually wired, retain one group-placement service and dedicated shared queue per worker, injecting the existing `createOperationQueue()` structurally. This queue must differ from any outer coordinator queue whose active job awaits `place`, to avoid a nested queue deadlock. Serialization includes final verification and survives per-call failures within one service lifetime; it does not coordinate external actors, other instances or restarts. The production placement executor reuses this resolver and native methods directly inside the coordinator queue, never this nested queued service. The replacement executor independently supplies closure evidence and startup recovery around the production path.

Build checks scan typed source, including erased type imports, and inspect esbuild's emitted dependency graph. Source guards permit only the exact `rules/grouping` and `rules/duplicates` validators as dependencies outside `config/` for config validation, reject rules imports outside `rules/`, limit planning to planning/rules and execution to execution/planning, reject external packages (including scoped names) from these layers and browser globals in all four layers, and reject options/background coupling and UI code in worker bundles. The scanner uses the pinned TypeScript 7 AST scanner entry point, whose API must be rechecked during dependency upgrades. Package checks deliberately enforce this small project's invariants; they are not a general JavaScript security analyzer.

Browser smoke confirms load, options errors, byte-preserved v3 rules across reload and worker restart, unchanged v1/v2/invalid/future storage, unchanged tab/group snapshots, stopped/running CDP worker state and a fresh JavaScript realm after navigation. A compiler bundle generated in a temporary test fixture runs the same hand-checked literal/wildcard/query/hash/port matrix as Node against native Chromium `URLPattern`. A separate temporary bundle runs the shared duplicate corpus against native Chromium `URL`/`URLSearchParams`, including invalid bytes, empty tokens and context separation. No fixture enters the extension package. Production-dist placement browser tests additionally prove observable grouping, membership, order, retained IDs and winner history. Deterministic synchronous registration, navigation dispatch and delayed initialization are covered by integration tests. There is no production test endpoint or worker keep-alive.

An isolated temporary extension fixture bundles the actual group placement service/adapter for real browser tests of creation, reuse, exact titles, duplicate selection, own-window isolation, pinning, last-member removal and partial failure. It records Chromium version, Chrome-owned collapse state and extension incognito capability. Incognito access is unavailable unless explicitly enabled for that fixture; a capability result is not a claim of incognito placement coverage. See Task 003 for the unautomated disposable-profile check.


Navigation admission is synchronous before any configuration await. Active ordinary committed metadata can establish document provenance even at cold worker start. Core reload (including address-bar-qualified reload), start_page, missing/unknown metadata and nonactive lifecycle cannot. Server redirects use final commits; qualified client redirects require trusted source provenance preserved across before-navigate. History/fragment updates require the trusted document, changed native href and no pending full navigation. No-op updates revoke work; delayed foreign-document events cannot acquire provenance. Both replacement APIs clear both identities/provenance and block the added ID without rank transfer. Error/canceled navigation remains conservatively blocked until a later active commit.

This is a metadata policy, not human-intent or universal restoration detection. **Unqualified script navigation reported as ordinary link can qualify after reload or cold worker start.** A real Chromium worker-restart probe observed exactly that admission for a delayed script; it did not report client_redirect. Qualified cold-client rejection is unit gated; the immediate trusted client redirect is browser observed. Ambiguous external launches (`start_page`), cold SPA/hash events and prerender activation without a qualifying commit are deliberate false negatives. See [Task 004](tasks/todo/004-navigation-eligibility-and-winner-selection.md) for policy and manual capability gaps.

Tracker epochs are fresh Symbols; numeric generations/sequences never cross worker lifetimes or persistence. Whole-view revisions include previously unobserved anchor invalidation. State retains only latest per-tab fingerprint, trusted document, eligible event and block status. Views and returned selections contain detached frozen observations. Selector inputs contain no Chrome/background types. It validates unique IDs/counters/context and obtains identity only from the supplied duplicate compiler using snapshot URLs/incognito. PendingUrl property presence, pinning, blocking or snapshot/event native-href inconsistency excludes a participant. Strict native URL freshness is independent of relaxed duplicate equivalence. Latest observed eligible sequence wins, with lowest-tab-ID ties; passive duplicates are ordered by winner window, window ID/index/tab ID for anchor choice.

The production placement consumer captures a tracker view BEFORE the existing all-normal-windows snapshot read and verify that same revision afterward, then revalidate event/view plus actual participant URLs/context/location around downstream async work. Pairing an old snapshot with a newly captured view is unsafe. Selections return no mutation plan or closure authority; production placement grants no closure authority. The temporary navigation browser bundle records real metadata and pending snapshots, worker-restart provenance loss and a bounded native prerender probe. No test endpoint, event fabrication or keep-alive enters production. Restore/reopen, external launch and trusted omnibox UI remain explicitly documented disposable-profile manual checks.


## Task005 production placement (previous placement-only phase)

`background/placement.ts` captures the tracker view before its all-normal-windows snapshot, compiles the captured grouping/duplicate rules and opts into lone-winner selection through the same validated selector path. `planning/replacement.ts` freezes one final destination and detached participants/baseline. Configured grouping resolves in the incoming window through003's pure resolver; without a rule the selected anchor supplies its window/group and after-anchor position. No destination means unchanged. Passive duplicate documents are optional; only the winner and a used inherited anchor receive frame0 document reads (at most two per observation round). Overridden duplicates never gate configured placement on their document availability. Task006 must obtain independent closure evidence.

`execution/placement.ts` owns no queue. Before each mutation it brackets used participant document checks with normal-window snapshots and checks the config/event/view lease around every await. A separate expected state accounts for acknowledged winner operations while the frozen plan stays unchanged. Nonwinner relative order/membership in source and destination windows, strict native URLs/context/pinning/pending state, source/destination group coherence/title/shared metadata and used document IDs stay guarded. A lone emptied old group/source window may disappear; surviving tabs may not. Known shared groups cannot acquire or lose the winner; absent shared metadata supports Chrome120.

The bounded operation sequence ungroups only when needed, moves across windows directly to the final destination boundary, joins/creates only the final group, titles a fresh group only when empty, and performs at most one final reorder. After-anchor index is computed with the winner removed exactly once. Final membership/window/order are authoritatively observed. Native focus/active/collapse changes are accepted and recorded by browser trials; production never explicitly changes them. No tabs are created/closed, no retry/rollback occurs, and mutation promises always settle before the coordinator queue releases. Results preserve original rejection causes and uncertain/acknowledged/verified effects; diagnostics emit only redacted `operation-failed` codes.

Repository `getCurrent()` publishes an in-memory revision lease only for the settled current operation. Load/save starts and disposal revoke it; a storage notification starts load synchronously. Coordinator contexts combine that publication with its own revision/disposal and event ownership. Consumer guards additionally require the captured whole tracker view, so unrelated navigation can cancel work conservatively. Default configuration remains disabled; manual schema3 enable/pause/backup/restore steps and browser capability limits are in the README. Native APIs cannot eliminate the final check-to-call race.

## Task006 journaled replacement and recovery

`execution/replacement.ts` wraps the existing queue-free placement executor and single-ID removals inside the coordinator job. It captures passive duplicate frame0 documents independently, without turning missing overridden documents into placement requirements. The final successful placement receipt is detached/frozen. Closure checks all remaining participant documents between coherent snapshots and compares affected windows/groups to that receipt minus verified removals. Strict original native href equality and original document IDs are required even with relaxed duplicate policy. Native active/focus/collapse changes remain accepted; all surviving IDs/order/membership/window/group title/color/shared/context/pin/pending evidence remains guarded. The single target must be authoritatively absent after native settlement before another removal can proceed.

`execution/journal.ts` owns strict bounded v1 parsing and serialized transitions through injected structural storage. The only key is `chromeReHomeReplacementJournal`, adapted by `browser/journal-storage.ts` to storage.session get/set/remove with unchanged trusted access. One record contains operationId, native participant IDs/context/document IDs, phase, mutation sequence, pending target, verified removed prefix and terminal state. Limits are 100 participants, 99 removals, 128 code units/string, 65536 serialized characters and 105 ordinals. More than 100 participants skips all mutation. No URL, identity/hash, title, configuration, error, timestamp, Symbol or tracker generation is persisted. Native document IDs are sensitive session metadata and never sufficient authority for replay.

Every placement mutation, including repeated move/final reorder, persists pending before repeating the entire original preflight. Both resolve/reject settlement paths clear pending durably; native rejection identity survives a second bookkeeping failure. Authoritative postverification precedes phase persistence. `placed` is durable before any close. Removal repeats full receipt/document/config/event checks after pending persistence, arms exactly one lease credit and invokes the one-ID native remove without another executor await. Terminal completion/abandonment precedes clear. Ambiguous storage failure blocks admission and never triggers repair writes. A preflight cancelled before native invocation may be abandoned by its still-live worker; restart cannot infer that distinction.

`background/navigation.ts` removal leases retain the original revision/epoch and immutable duplicate allowlist. Each issued ID credits only its first onRemoved event while the lease was current immediately before it. Earlier issued events may arrive during the next remove. An unexpected/duplicate event, navigation/invalidation or either replacement API remains fatal; later credited events never revive stale work. Consumer disposal permanently invalidates the lease. Ordinary tracker forgetting/revision advancement still occurs for every event.

`background/index.ts` constructs one native port, one session journal (operation IDs injected using crypto.randomUUID), one recovery object and one queue. Listeners register synchronously first. Coordinator initialization joins config loading with recovery on that same queue; consume jobs await the entire promise before enqueueing. Current config publication and recovery/journal readiness also remain part of running guards. Recovery runs regardless of enabled/config validity. Missing storage becomes ready; valid settled records await one read-only live snapshot as the reconciliation gate before clear/abandon; pending, malformed, future or unreadable records preserve data and quarantine all automatic mutation. Participant presence never authorizes replay. Read/clear failure blocks. A native call is never raced against a timeout, and a new worker cannot issue work across the persisted pending barrier even after an old worker's late effect/event. Recovery never replays placement/closure.

Full browser restart is the reliable reset for ambiguous native settlement, followed by an explicit fresh trial. Session clearing by disable/reload/update does not prove native settlement. Chrome has no atomic compare-document-and-remove operation; the residual final check-to-call race remains. No unsaved-form protection or stronger transaction guarantee is claimed. Existing enabled schema3 installations activate closure on upgrade; README begins with the pause-before-reload warning and options states configured replacement enablement plus a static interruption warning.

Automated evidence separates unchanged production dist (closure, native indices/history, seeded restart admission) from temporary phase fixtures (actual worker termination after durable writes, event-delivery races, simulated faults). Production has no test globals/endpoints/keep-alive. Pending-write gates are before native invocation; a separate fulfilled-remove wrapper gate proves already-issued effect without recorded settlement. Deterministic termination inside an outstanding native Chrome API remains unproven by the browser; deferred old-worker tests retain its unresolved call and show fresh-coordinator quarantine after late effects. Manual actual drag, incognito capability enablement, Chrome120/current-stable and user-facing focus/collapse trials remain required.
